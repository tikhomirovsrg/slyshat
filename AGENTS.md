# Слышать — инструкции для работы с проектом

Учебный сайт для русскоязычных пользователей: английский и итальянский, основной сценарий — истории и понимание речи на слух. По решению пользователя интерфейс оформлен как комикс: бумажный фон, чёткие контуры, цветные акценты. Сохраняйте существующий прогресс и адаптацию к телефону.

## Устройство
- Next.js App Router, React, TypeScript; Node.js 24. `app/page.tsx` — оболочка; `app/story-course.tsx` — единый каталог и комикс с выбором действий; `app/episodes.ts` — 40 исходных историй для совместимости.
- `lib/db-migrations.mjs` — последовательные транзакционные миграции SQLite. `lib/db.ts` — подключение. Docker запускает миграцию до сервера.
- `app/speech.tsx` / `lib/speech-player.ts` — общий владелец воспроизведения. Новый звук останавливает старый. Не создавайте независимую конкурирующую озвучку.
- `public/audio/` — готовые записи; `scripts/audio-library/` — воспроизводимая генерация большого каталога. Синтез и скачивание весов не нужны для запуска сайта.
- Yandex ID — серверная авторизация; прогресс и профиль синхронизируются через существующие API.

## Правила
1. Не меняйте байты применённых `content/catalog-v1.json` и `content/practice-v2.json`. Новые материалы — новый версионированный выпуск, без сброса данных пользователей.
2. Различайте интерактивные истории, сценарные варианты, планы и реально готовые записи. Не приписывайте каталогу отсутствующий контент.
3. A1–C1 — педагогические ориентиры. Сложность определяется языком и заданиями, а не скоростью воспроизведения; официальной сертификации CEFR нет.
4. Открытый текст означает помощь чтением. Прослушивание, правильный ответ и освоение урока — разные события. Прерванное воспроизведение не завершает аудирование.
5. Не отправляйте пользовательские черновики в синтез; не добавляйте ключи, `.env`, БД, бэкапы, модели и виртуальные окружения в Git. Секреты остаются на сервере.
6. Публикация в GitHub и обновление пользовательского Docker-сервера — разные действия. Сообщайте, какое реально выполнено.

## Проверка
`npm run check`, `npm test`, `npm run build`, затем `npm run test:production`.
Не запускайте TypeScript-проверку одновременно со сборкой Next: `.next/types` перезаписывается.
Для аудио проверяйте ссылки, контрольные суммы, длительности, остановку, переключение и завершение. Техническая проверка не заменяет прослушивание носителем.
Docker: смотрите `compose.yaml`, `Dockerfile`, `docs/OPENCLAW-NEXT.md` и актуальные документы в `docs/`.

## Комиксы и прохождение по порядку
- `content/story-course/course-v1.json` — неизменяемый выпуск: по 1000 историй на язык, по 200 на уровень. Включает прежние 20 на язык; остальные — интерактивные варианты, это не тысяча независимых сюжетов.
- `lib/story-course-migration.mjs` добавляет выпуск в SQLite (схема 6). `GET /api/stories` отдаёт компактный каталог; граф и аудио загружаются только при открытии истории.
- `StudyProfile.journey` хранит выбранный маршрут, помощь текста и активную историю. Старые `progress`, `runs`, `audioPractice`, черновики и упражнения не удаляются.
- Номер задаёт порядок внутри языка. Следующая история определяется по полному каталогу, а не по фильтрам или странице. Свободный выбор разрешён.
- Переход к финалу означает завершение сюжета, а не освоение CEFR. Выбор действий не оценивается как правильный/неправильный ответ.
- `public/audio/course` содержит новые готовые записи, `public/audio/library` — также используемые сцены. Оба каталога нужны для запуска. Перед публикацией выполняйте `npm run course:validate`.
- Телеметрия ONNX Runtime отключается до создания сессии; генератор не требует сетевого синтеза.

- `lib/playback-speed.ts` задаёт доступные скорости, совместно для интерфейса и валидации сохранений. Изменение скорости записи через общий проигрыватель не сбрасывает позицию и не засчитывает дослушивание.
- `restartJourney` сбрасывает только текущую попытку; сохраняйте `completedAt` и `endings`. Перезапуск должен отменять текущую последовательность аудио даже на первом кадре.
- `app/comic-scene-art.tsx` привязывает иллюстрацию к текущей сцене и уже выбранному маршруту. Сохраняйте скрытие реплик, отключение движения при reduced motion и адаптивную высоту шапки.

## Рисованные комиксы (3.2)
- Все герои — антропоморфные животные с человеческой одеждой, занятиями и жестами. Сохранять приключенческий стиль для взрослых, постоянную внешность между сценами; обычных людей вместо героев не добавлять.
- `app/comic-stage.tsx` / `app/comic-novel.css` — основной рисованный экран. `docs/COMICS.md` описывает персонажей, ограничения и следующий этап.
- SQLite 7 добавляет `comic_boards` и `comic_releases`. `content/comics/comic-v1.json` и рецепт v1 в `lib/comic-migration.mjs` после публикации неизменяемы. Сохранять старые графы и озвучку.
- Иллюстрации ImageGen находятся в `public/comics/v1`, запросы и контрольные суммы — в манифесте. Все 2000 постановок используют восемь общих локаций и двух визуальных актёров; не называть их уникальными рисунками для каждого сюжета.
- Осмотр перевода — помощь чтением. Не раскрывать неоткрытые финалы. Поза следует аудиопозиции; статичный режим сохраняет все действия. Выполнять `npm run comics:validate`.

- Клиентские SyncEngine/ProfileSync используют `lib/client-request.ts`: сохранять глобальный контекст браузерного fetch и тайм-аут на всё чтение JSON. Не вызывать переданный native fetch как метод экземпляра. Регрессия проверяется в `tests/client-request.cjs`.
