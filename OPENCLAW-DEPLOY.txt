Релиз 3.0: комиксы с выбором сюжета, по 1000 на язык. SQLite-схема 6. Подробности: docs/STORY-COURSE.md.

Разверни «Слышать» из этого Git-репозитория рядом с собой — на том же постоянном хосте, где работает OpenClaw Gateway. Используй отдельный Docker Compose-проект slyshat. Не меняй и не останавливай OpenClaw.

В репозитории единый курс: по 1000 интерактивных комиксов на английском и итальянском, уровни A1–C1, готовые записи, Яндекс ID и прогресс в SQLite. Исходные 20 историй на язык сохранены внутри курса; дополнительные варианты переиспользуют сцены. Прочитай AGENTS.md, docs/STORY-COURSE.md, README.md и используй существующие Dockerfile и compose.yaml.

1. Проверь доступ к хосту, Docker и Compose v2. Если работаешь в контейнере/sandbox, используй разрешённый доступ к хосту Gateway. Не устанавливай приложение внутри временного sandbox и не обходи ограничения доступа. Машину выбирать не нужно: размещай на своём хосте.

2. Клонируй этот репозиторий в отдельную постоянную папку, например /opt/slyshat, используя имеющийся разрешённый доступ к GitHub. Если установка уже существует, сначала сделай резервную копию; сохрани .env, имя Compose-проекта и прежний том базы. Не удаляй данные.

3. Проверь свободные порты. Если 3000 занят, выбери другой LOCAL_PORT. Создай .env из .env.example только при отсутствии файла:
APP_URL=https://ДОМЕН-ПРИЛОЖЕНИЯ
LOCAL_PORT=3000
YANDEX_CLIENT_ID=идентификатор
YANDEX_CLIENT_SECRET=секрет
YANDEX_ALLOWED_LOGINS=мой_логин

Не оставляй обозначения вместо реальных значений. Ограничь права .env до 600. Не печатай секреты в чат или журналы. Используй доступное хранилище секретов либо попроси меня заполнить файл на сервере.

Для Яндекс ID нужны право login:info и Redirect URI:
https://ДОМЕН-ПРИЛОЖЕНИЯ/api/auth/yandex/callback
APP_URL должен совпадать с адресом сайта. Если домен, логин или OAuth-параметры неизвестны, спроси только недостающие данные одним сообщением.

4. Для доступа с разных устройств настрой отдельный HTTPS-домен. При свободных 80/443 и правильном DNS используй Caddy из комплекта:
docker compose --env-file .env config --quiet
docker compose --env-file .env --profile https up -d --build

Если 80/443 уже занимает прокси, добавь в него отдельный сайт для приложения и запусти только app:
docker compose --env-file .env up -d --build

Не занимай адрес панели OpenClaw. Для прокси на хосте upstream — 127.0.0.1:LOCAL_PORT; для контейнерного прокси настрой общую сеть и app:3000.

Для временной локальной проверки допустим APP_URL=http://localhost:LOCAL_PORT без профиля https. С другого устройства localhost недоступен. Не считай такую проверку завершённым общим доступом.

5. Проверь healthy у app, HTTP 200 на главной и /api/health, действительный HTTPS. Без входа /api/progress и /api/profile должны отвечать 401. Проверь реальный вход через Яндекс, сохранение ответов, черновика и учебной цели после перезагрузки и перезапуска app. Затем проверь загрузку прогресса в другом браузере под тем же аккаунтом. Если нужен мой вход, попроси выполнить только этот шаг. Убедись, что OpenClaw продолжает работать.

6. Создай резервную копию из папки проекта:
umask 077
mkdir -p backups
docker compose --env-file .env exec -T app node scripts/backup.mjs > backups/progress.sqlite

Не перезаписывай прежнюю копию: выбери новое имя, если файл существует. Проверь успешный код команды и целостность копии. Не выполняй down -v и не удаляй Docker-тома. Обновления делай после бэкапа через up -d --build с сохранением тома.

В конце сообщи URL, папку проекта, порт, имя тома, путь к бэкапу и результаты проверок. Отдельно перечисли непроверенное. Сохрани эти сведения без секретов в DEPLOYMENT-NOTES.txt. Работающий контейнер без настроенного входа — ещё не готовый сайт.
