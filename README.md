# «Слышать» — самостоятельное развёртывание

**Версия 3.0: комиксы с озвучкой и выбором сюжета.** По 1000 историй на язык, по 200 на уровень A1–C1, прохождение по порядку и общий прогресс. Включены прежние 20 историй на язык; остальные — интерактивные варианты с общими сценами. [Устройство курса и обновление Docker](docs/STORY-COURSE.md).

Единый каталог читает 2000 интерактивных комиксов из SQLite. У новых вариантов два последовательных решения и четыре разных финала. Истории можно проходить по порядку или выбирать самостоятельно. Интерфейс и переводы — на русском, реплики — на английском или итальянском.

Старые 40 историй включены в курс с прежними ID. Их упражнения, чтение, словарь, письменные работы и результаты сохранены. Исторические выпуски материалов остаются в базе; они не прибавляются к числу новых историй.

Пошаговый план развёртывания и дальнейшей разработки для OpenClaw: [docs/OPENCLAW-NEXT.md](docs/OPENCLAW-NEXT.md).

## Что входит

- По 1000 интерактивных историй на язык: комикс, готовое аудио, выбор реплик и развязка. Порядок 1–1000, уровни A1–C1, продолжение между устройствами.
- 40 учебных блоков уровней A1–C1: словарь, грамматика, чтение, 632 закрытых упражнения с объяснениями (312 основных и 320 в коротких дополнительных блоках) и письменная практика.
- Входной тест из 20 заданий и контрольные из 12; повторение ошибок, интервальное повторение слов, статистика и ежедневная цель.
- Готовые синтетические записи двух голосов на язык, регулировка скорости, текст и перевод по желанию.
- Next.js / React, собранные в production-режиме `standalone`.
- Яндекс OAuth Authorization Code + PKCE, одноразовый `state`, серверные сессии в HttpOnly-cookie.
- SQLite на сервере, в постоянном Docker-томе `progress_data`.
- SQLite-схема 7: 2000 постановок рисованных комиксов и 2000 записей общего курса плюс сохранённые исторические материалы и учебные блоки. Миграция запускается при старте Docker.
- Отдельные сохранения каждого пользователя и каждой истории, продолжение на другом устройстве: ответы, письменные черновики, самопроверка, словарь, результаты тестов и настройки учебного профиля.
- Очередь несохранённых изменений в браузере, повторная синхронизация при восстановлении связи.
- Выбор версии при одновременном изменении одной истории на двух устройствах.
- История последних 100 завершённых прохождений, которая сохраняется при повторном старте истории.
- Импорт старых JSON-сохранений и экспорт текущего прогресса.
- Необязательный Caddy для HTTPS, healthcheck и скрипты резервного копирования.

Комиксы воспроизводят включённые в репозиторий MP3 без ключа синтеза. Google Chirp и системные голоса остаются опциями для словаря и дополнительных материалов: [настройка](docs/AUDIO.md). Завершение комикса означает достижение финала, не оценку CEFR. Правила освоения прежних учебных блоков и письменная самопроверка сохранены в архиве прогресса.

## Быстрый запуск на компьютере

Нужен Docker с Compose v2. Для входа понадобится своё OAuth-приложение в Яндексе; без него сайт откроет экран «Вход пока не настроен».

```bash
cp .env.example .env
```

В `.env` оставьте `APP_URL=http://localhost:3000`, внесите Client ID и Client Secret по инструкции ниже. Затем:

```bash
docker compose up -d --build
docker compose ps
```

Откройте http://localhost:3000. Порт приложения привязан к `127.0.0.1`: эта конфигурация предназначена для локальной проверки. Для телефона и компьютера через интернет используйте домен и HTTPS из следующего раздела.

## Запуск на сервере с HTTPS

1. Направьте DNS A-запись вашего домена на сервер. Если задана AAAA-запись, IPv6 тоже должен вести на этот сервер.
2. Откройте входящие TCP-порты 80 и 443; UDP 443 необязателен, он используется для HTTP/3.
3. Создайте `.env` из примера, установите `APP_URL=https://english.example.com` и внесите параметры Яндекса. Замените домен своим.
4. Запустите:

```bash
docker compose --profile https up -d --build
docker compose ps
docker compose logs --tail=80 app caddy
```

Caddy получает и обновляет сертификат и направляет запросы к приложению. Данные сертификатов также хранятся в постоянных томах. На обоих устройствах откройте **один и тот же домен** и войдите в **один и тот же аккаунт Яндекса**.

Если HTTPS уже обеспечивает ваш reverse proxy, запускайте только `app` и направьте прокси на `127.0.0.1:3000`. `APP_URL` всё равно должен содержать внешний HTTPS-адрес. Секреты не включаются в Docker-образ; они передаются приложению при запуске.

## Настройка Яндекс ID

Откройте https://oauth.yandex.ru/client/new/id/ под вашим аккаунтом разработчика и создайте приложение **для авторизации пользователей**.

| Поле | Значение |
| --- | --- |
| Название | Слышать |
| Платформа | Веб-сервисы |
| Redirect URI для сервера | `https://ВАШ-ДОМЕН/api/auth/yandex/callback` |
| Redirect URI для локальной проверки | `http://localhost:3000/api/auth/yandex/callback` |
| Необходимое право | `login:info` — основная информация о пользователе |

Укажите иконку и контактную почту в форме Яндекса. Redirect URI должен соответствовать `APP_URL` и пути callback. Для локальной проверки используйте адрес, который разрешает зарегистрировать кабинет Яндекса; если localhost недоступен, проверяйте через свой HTTPS-домен.

Скопируйте Client ID и Client Secret из свойств приложения в `.env`. **Не публикуйте `.env` и не вставляйте секрет в клиентский код.** Пароль Яндекса этому сайту не нужен. Токен Яндекса используется только на сервере при входе для получения профиля и не сохраняется; дальнейшие запросы используют собственную серверную сессию.

| Переменная | Назначение |
| --- | --- |
| `APP_URL` | Внешний адрес без пути: `https://english.example.com`. Вне localhost обязателен HTTPS. |
| `LOCAL_PORT` | Порт на localhost хоста, по умолчанию 3000. |
| `YANDEX_CLIENT_ID` | Идентификатор OAuth-приложения. |
| `YANDEX_CLIENT_SECRET` | Секрет OAuth-приложения. |
| `YANDEX_ALLOWED_LOGINS` | Необязательный список разрешённых логинов через запятую. Для личного сайта укажите свой логин. Пустой список разрешает создание отдельных профилей любым аккаунтам Яндекса. |

После изменения `.env` повторите `docker compose --profile https up -d` (или без профиля при локальном запуске).

Если Яндекс отменил вход, вернул ошибку или аккаунт не входит в список разрешённых, сайт покажет сообщение без раскрытия токенов. Проверьте Client ID, Secret, Redirect URI и список логинов. Неверифицированное приложение может показывать предупреждение Яндекса; порядок верификации описан в документации провайдера.

## Перенос прогресса со старого сайта

Хранилище браузера привязано к домену: новый сервер не может автоматически прочитать данные с адреса ChatGPT Sites.

1. На старом сайте https://slyshat-coffee.grassydream8.chatgpt.site откройте настройки и скачайте прогресс.
2. На новом сайте войдите через Яндекс ID.
3. В настройках выберите «Загрузить» и укажите JSON-файл. Поддерживаются старые сохранения одиночной истории и коллекции, а также новый экспорт всех 40 историй с учебным профилем и черновиками. Вход ChatGPT на размещённом сайте и вход Яндекса на вашем сервере — независимые аккаунты; автоматической связи между ними нет.
4. Дождитесь статуса **«Сохранено в аккаунте»**. Теперь этот прогресс доступен с другого устройства.

Если прежние локальные данные уже есть на том же домене, появится предложение перенести их в аккаунт. При расхождении с сервером сайт предложит выбрать сохранение. Перед заменой прогресса из JSON есть подтверждение.

## Как работает сохранение

Прогресс включает позицию в диалоге, ответы, результаты, сохранённые фразы, письменные черновики, самопроверку и интервалы повторения. Учебный профиль отдельно хранит выбранный уровень, цель, результаты тестов и историю учебной активности. Он отправляется после изменений с небольшой задержкой. Новое устройство получает серверную копию после входа. Проверка обновлений происходит при возвращении во вкладку, восстановлении связи, вручную и раз в 30 секунд.

При обрыве связи изменения остаются в локальной очереди именно этого аккаунта. Они отправятся после восстановления соединения. До статуса «Сохранено в аккаунте» очистка данных браузера может удалить неотправленные изменения. Полноценная офлайн-установка/PWA в эту версию не входит: для первого открытия страницы и входа нужен интернет.

У каждой истории и учебного профиля есть ревизия. Устаревшая запись не заменяет более новую автоматически: нужно выбрать локальное или серверное сохранение. Завершённые попытки хранятся отдельно от текущей позиции. На сервере идентификатор пользователя берётся из проверенной сессии; переданный клиентом идентификатор не даёт доступа к чужим данным.

## Резервная копия

Том сохраняет данные при пересоздании контейнера, но не заменяет резервную копию на другом носителе. Используйте онлайн-бэкап SQLite, а не копирование одного `.sqlite` без WAL-файла:

```bash
umask 077
mkdir -p backups
docker compose exec -T app node scripts/backup.mjs > backups/progress.sqlite
```

Команда сохраняет все аккаунты, прогресс, черновики, учебные профили, историю, каталог материалов и план развития. Скопируйте файл на другой защищённый носитель. Для нескольких копий используйте разные имена. Токены Яндекса в базе не хранятся.

Восстановление выполняется при остановленном приложении:

```bash
docker compose stop app
docker compose run --rm --no-deps -T app node scripts/restore.mjs --confirm-app-stopped --archive-existing < backups/progress.sqlite
docker compose up -d app
```

Скрипт проверит целостность и версию базы. Предыдущая база и её WAL/SHM-файлы сохранятся рядом с суффиксом `.before-restore-...`. Старые сессии из восстановленной копии будут отозваны: нужно войти заново. Запускайте восстановление только когда все экземпляры приложения остановлены.

Обычный `docker compose down` сохраняет тома. **`docker compose down -v` удаляет серверную базу и сертификаты.**

## Обновление и ограничения

Перед обновлением сделайте резервную копию, замените исходники в прежней папке, сохранив ваш `.env`, и выполните:

```bash
docker compose --profile https up -d --build
```

При обновлении предыдущего Docker-комплекта схема базы автоматически переходит с версий 1–6 на 7. В версии 2 добавлялись учебные профили; версия 3 добавляет каталог, документы проекта и журнал загрузки материалов; версия 4 — 80 дополнительных блоков практики и журнал их выпусков; версия 5 — 2000 сценарных аудиовариантов и их озвученные сцены. Версия 6 добавляет общий курс, версия 7 — постановку рисованных комиксов. Аккаунты, сессии, письменные черновики, профили и прохождения сохраняются. Не меняйте имя Compose-проекта `slyshat` и не удаляйте том `progress_data`. Для отката к старому приложению используйте резервную копию базы до обновления.

Приложение запускается не от root. SQLite работает в WAL-режиме. Контейнер сначала выполняет миграцию, затем запускает сервер; при ошибке миграции сервер не стартует. При запуске вне контейнера та же миграция выполняется при первом открытии БД. В этой конфигурации запускайте **один экземпляр `app`** и храните том на локальном диске сервера. Несколько вкладок и устройств поддерживаются; горизонтальное масштабирование контейнеров потребует отдельного решения для базы и миграций.

## Автоматическая загрузка каталога

Для новой установки и обновления достаточно `docker compose up -d --build`. Скрипт `scripts/docker-entrypoint.sh` перед `server.js` запускает `scripts/migrate.mjs`. Отдельная команда импорта и готовый файл SQLite не нужны. Весь набор материалов находится внутри образа; для импорта не требуется внешний сервис.

Миграции материалов создают таблицы:

| Таблица | Данные |
| --- | --- |
| `content_stories` | 200 записей: язык, название, целевой уровень, текущий уровень практики, статус, серия, цель аудирования, сюжетное задание; у 40 доступных историй также полный JSON диалога и учебного блока |
| `project_documents` | План развития, этапы выпуска, критерии готовности, структура занятия и весь каталог |
| `content_seed_versions` | Версия загрузки, контрольная сумма и время применения |
| `content_practice_sets` | 80 дополнительных блоков, 320 вопросов с ответами, объяснениями, текстами и сценами для озвучки |
| `content_practice_releases` | Версия дополнительной практики, контрольная сумма и количество материалов |

На каждом языке целевое распределение: A1 — 20, A2 — 30, B1 — 30, B2 — 15, C1 — 5. `available` означает одну из 40 уже реализованных историй; `planned` — одну из 160 заготовок. Независимая оценка уровня аудирования ещё не выполнена: `listening_level` остаётся `NULL`. Настройка озвучки и число готовых историй от миграции не меняются.

Схема и загрузка применяются в одной транзакции. Повторный запуск не создаёт дублей, не переписывает редакторские изменения и не затрагивает таблицы прогресса. Повторное использование того же `seedId` с изменённым содержимым блокируется. Для обновления уже импортированной записи нужна отдельная явная миграция; новый набор с новым `seedId` добавляет только отсутствующие записи.

Исходный план находится в `content/planning.json`. `content/catalog-v1.json` — неизменяемый исторический набор. `npm run content:build` проверяет его и новый `content/practice-v2.json` перед production-сборкой, не перезаписывая исторический файл. Игровой интерфейс пока читает 40 встроенных материалов приложения. База хранит их полную копию и редакционный план; редактор материалов и загрузка уроков из БД в интерфейс — отдельный следующий этап.

Проверка после запуска:

```bash
docker compose logs --tail=50 app
docker compose exec -T app node scripts/migrate.mjs
```

Повторная команда должна вывести `schemaVersion: 7`, `seeded: false`, `practiceSeeded: false`, `audioSeeded: false`, `courseSeeded: false`, `comicsSeeded: false`, `comicBoards: 2000`, `practiceSets: 80`, `practiceQuestions: 320`, по 20 `available` и 80 `planned` на каждый язык и один документ. Для локального запуска без Docker используйте `npm run db:migrate`; путь по умолчанию — `./data/slyshat.sqlite`, либо заданный `DATABASE_PATH`.

Команды резервного копирования и восстановления обходят стартовую миграцию; после восстановления старой базы миграция выполнится при обычном запуске приложения. Поддерживаются резервные копии схем 1–7.

Контейнеру нужен исходящий HTTPS к `oauth.yandex.ru` и `login.yandex.ru`. Caddy нужен доступ к центрам сертификации.

## Разработка и проверки

Локально нужен Node.js 24:

```bash
npm ci
npm test
npm run check
npm run build
npm run test:production
```

Для разработки загрузите переменные `.env` и запустите `npm run dev`. Next.js читает `.env` автоматически. Для production вне Docker можно использовать `npm start` после сборки, обеспечив постоянный `DATABASE_PATH`.

Тесты покрывают изоляцию аккаунтов, серверные сессии, OAuth state/PKCE, отказ посторонним Origin, повторные запросы, конфликт двух устройств, очередь после обрыва связи, смену аккаунта, перенос локальных данных и сохранение истории при сбросе текущей попытки. OAuth-провайдер в тестах имитируется; реальный вход нужно проверить с вашим приложением Яндекса.

- Установка зависимостей из переносимого `package-lock.json`; локальных ссылок в нём нет.
