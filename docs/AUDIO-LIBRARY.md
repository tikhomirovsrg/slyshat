# Аудиобиблиотека 2.4

В разделе «Аудио» добавлены **1000 сценарных аудиовариантов на английском и 1000 на итальянском**. Это открыто описанная комбинаторная серия: 25 ситуаций × 8 поворотов × 5 уровней. Общие сцены переиспользуются; это не 2000 независимых авторских сюжетов. Существующие 40 интерактивных историй и 160 строк плана не заменяются этим каталогом.

| Уровень | Вариантов на язык | Объём текста | Основная задача |
|---|---:|---:|---|
| A1 | 200 | 61–85 слов | Явные факты, время, место, простое решение |
| A2 | 200 | 118–145 слов | Прошедшие события, причина и план |
| B1 | 200 | 158–197 слов | Связь причины, выбора и последствий |
| B2 | 200 | 207–233 слова | Доводы, компромиссы, предположения |
| C1 | 200 | 282–320 слов | Неявные основания, границы довода, участие |

Разметка уровней педагогическая, не внешняя экспертиза CEFR. Реальная длительность отображается по записи; скорость регулируется отдельно. Сюжеты посвящены совместным делам: встречи, работа, город, путешественники, культурные и соседские инициативы. В каждом варианте завязка, проблема, ответ второго участника и итог, русский перевод и три проверяемых вопроса. Всего 6000 предъявлений вопросов; формулировки и сценические блоки повторяются между вариантами.

## Как пользоваться

Открой «Аудио», выбери уровень, тему или поиск, затем историю. Прослушай целиком и ответь на три вопроса. Если открыт текст, попытка отмечается как работа с текстом, даже после его повторного скрытия. После проверки доступны правильные ответы и объяснения. Результаты сохраняются в учебном профиле через существующую синхронизацию аккаунта; в каталоге виден последний результат. Это не автоматически освоенный интерактивный урок и не оценка произношения.

На английском звучат Emma и George, на итальянском Sara и Nicola. Это заранее созданный синтез Kokoro, без API-ключа при воспроизведении. Технические проверки не заменяют экспертное прослушивание: качество произношения всех материалов носителем не проверено.

## Файлы и база

- `content/audio-library/series-v1.json`: неизменяемый выпуск, 2000 сценариев, 420 уникальных озвучиваемых сцен, вопросы и переводы.
- `public/audio/library/`: 10 MP3-контейнеров (язык × уровень) и манифест с границами сцен, длительностями и SHA-256.
- Каждая история воспроизводит четыре отрезка готовых файлов. **В Git находятся 10 общих MP3-контейнеров, а не 2000 дублирующих MP3-файлов.** Все 2000 последовательностей полностью озвучены. Кнопка запуска не генерирует речь.
- `public/audio/kokoro/`: прежние шесть демонстрационных MP3; они доступны под пунктом сравнения голосов.
- Миграция SQLite v5 добавляет `audio_content_releases`, `audio_content_segments`, `audio_content_stories`. Пользовательские данные остаются в прежних таблицах. Повторный запуск не дублирует материал и проверяет хеш выпуска.
- Docker уже включает исходник каталога и аудио. Модель и Python на сервере сайта не нужны. Аудио входит в образ, прогресс — в постоянный том `progress_data`.

## Воспроизводимая генерация

Требуются Python 3.12, ffmpeg/ffprobe и зависимости из `scripts/kokoro-samples/requirements.txt`. Веса не входят в Git. Источник весов: официальный выпуск [kokoro-onnx model-files-v1.1](https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.1). Модель Kokoro-82M v1.0 распространяется под Apache-2.0; kokoro-onnx — под MIT.

Проверяемые SHA-256:

- `kokoro-v1.0.onnx`: `beb0d1848dee9a49da392cc3df26958d46cfa35d321edf434f52949153f0df3a`
- `voices-v1.0.bin`: `bca610b8308e8d99f32e6fe4197e7ec01679264efed0cac9140fe9c29f1fbf7d`

Из корня репозитория, после установки зависимостей в отдельное окружение:

```bash
python scripts/audio-library/generate.py \
  --model /path/to/kokoro-v1.0.onnx \
  --voices /path/to/voices-v1.0.bin \
  --cache /path/to/audio-cache \
  --workers 2 --threads 2
npm run audio:validate
```

Генератор сверяет веса, сохраняет PCM по хешу текста/голоса/параметров, продолжает после прерывания, затем собирает MP3 и проверяет полное декодирование. Манифест публикуется только после окончания всей генерации. Не обновляйте рабочую папку живого сервера во время генерации: подготовьте выпуск отдельно, затем пересоберите контейнер. Изменённые тексты требуют нового выпуска и согласованных записей.

`build-source.py` документирует сборку вариантов из написанных сцен. Он воспроизводит исходник, но не обращается к языковой модели и не создаёт бесконечный поток новых сюжетов. Уже опубликованный выпуск изменять нельзя.

## Отдельные MP3

При необходимости получить самостоятельные файлы без переиспользования сцен:

```bash
python scripts/audio-library/export.py --id it-a1-dinner-time --output /path/to/export
python scripts/audio-library/export.py --all --output /path/to/export
```

Экспорт требует только Python и ffmpeg, читает уже созданное аудио и ничего не синтезирует. `--all` создаёт 2000 файлов и заметно увеличивает объём. Папку экспорта храните вне checkout; она не нужна для работы сайта.

## Обновление через OpenClaw

Сделай бэкап по README, сохрани `.env`, имя Compose-проекта и `progress_data`. Затем:

```bash
git pull --ff-only
docker compose up -d --build app
docker compose exec -T app node scripts/migrate.mjs
```

Ожидается схема 5 и по 200 аудиовариантов каждого уровня на язык. Проверь `/api/audio/library?language=it&level=A1`, переключение на C1 и английский, полное проигрывание, остановку, раскрытие текста и результат после входа со второго устройства. Для обновления этих записей Google Cloud не нужен. `docker compose down -v` не применять. Публикация коммита сама по себе не обновляет сервер.
