# Нейроозвучка — версия 2.3

Вместо зависящего от устройства синтеза можно включить Google Cloud Text-to-Speech, модель Chirp 3 HD. На английском (`en-GB`) и итальянском (`it-IT`) доступны четыре варианта: Aoede и Kore — женские, Charon и Puck — мужские. Другие локали английского, если они указаны в учебном задании, сохраняются.

По умолчанию основной участник использует Aoede, второй участник и ответы ученика — Charon. В «Звук и прогресс» можно сравнить образцы, выбрать голоса отдельно и изменить скорость. Настройки сохраняются для каждой истории в аккаунте и синхронизируются между устройствами. Старые системные настройки не препятствуют включению нейроголосов; для намеренного использования устройства есть отдельная группа выбора.

Общий плеер используется в историях, словаре, дополнительных заданиях, тестах и воспроизведении диалога по ролям. Весь диалог проигрывается по репликам; первая генерация может давать паузы. Остановка, переключение раздела и ошибка не засчитываются как завершённое прослушивание. Открытый текст по-прежнему переводит ответ в чтение. Запись микрофона не отправляется провайдеру, автоматической оценки произношения нет.

## Включение на сервере / задание OpenClaw

1. Сохрани онлайн-бэкап SQLite согласно README. Сохрани существующий `.env`, имя Compose-проекта `slyshat` и том `progress_data`.
2. Обнови рабочую копию: `git pull --ff-only`. При локальных изменениях остановись и сохрани их; не делай `reset --hard`.
3. В Google Cloud нужен проект с подключённой оплатой и включённым **Cloud Text-to-Speech API**. Создай API key для этого API, ограничь его этим сервисом и, если есть постоянный исходящий IP сервера, этим IP. Это не ключ Gemini из AI Studio и не данные Яндекс ID. Доступность сервиса и оплаты для своего аккаунта нужно проверить в Google Cloud.
4. Внеси значения в серверный `.env` через защищённый редактор. Не отправляй ключ в чат, Git или журналы. Не добавляй префикс `NEXT_PUBLIC_`.

```dotenv
TTS_PROVIDER=google
GOOGLE_TTS_API_KEY=<ключ на сервере>
TTS_DAILY_CHAR_LIMIT=20000
```

Значение 20000 — технический предел символов для новых записей за сутки UTC на весь сайт. Это не денежный бюджет Google. Один текст, созданный четырьмя голосами, расходует лимит четыре раза. Неудачный запрос также резервирует лимит: провайдер мог принять его до сетевого сбоя. Лимит хранится на диске и не сбрасывается перезапуском приложения. `0` разрешает только ранее сохранённые записи. Отдельно настрой квоты и уведомления о расходах в Google Cloud.

5. Пересобери и пересоздай приложение с новыми переменными. Простой `restart` не перечитывает `.env`.

```bash
docker compose up -d --build app
docker compose ps
```

Если Caddy уже обслуживает сайт, эта команда его не заменяет. Для первоначального развёртывания HTTPS используй существующую инструкцию README. `APP_URL`, Яндекс ID и домен менять не требуется. Не используй `docker compose down -v`.

6. Открой `/api/audio/config` на своём домене: ожидаются `provider: "google"` и `ready: true`. Этот статус означает наличие конфигурации, а не успешный платёж или проверку ключа у провайдера.
7. Войди в приложение. На одной итальянской и одной английской истории открой «Звук и прогресс». Послушай Aoede, Charon, Kore и Puck. Проверь различимость голосов, ударения, числа, совпадение реплик с текстом и отсутствие обрезанных концов. Затем проверь диалог по ролям и упражнение без открытого текста на телефоне и компьютере.
8. Повтори одну реплику и перезапусти приложение. Повтор должен использовать сохранённый MP3. Остановленный фрагмент не должен разрешать ответ как прослушанный; открытие текста должно учитываться как чтение. Проверь, что выбор голосов доступен после входа со второго устройства.

Платная массовая генерация всей библиотеки не запускается при сборке, миграции или старте. Записи создаются по запросу авторизованного пользователя. Для начала достаточно образцов и двух историй; расширять пилот стоит после проверки качества и расходов.

## Хранение и бэкапы

Compose задаёт `AUDIO_CACHE_PATH=/data/audio` внутри существующего постоянного тома `progress_data`. При пересоздании контейнера MP3 и `usage.sqlite` сохраняются. Файлы общие для пользователей: провайдер получает только опубликованные учебные тексты, без прогресса, черновиков или записей микрофона.

Ключ файла зависит от текста, локали, модели, голоса и формата. Изменение текста или голоса создаёт другую запись; скорость меняется в браузере с сохранением высоты тона. Одновременные одинаковые запросы объединяются. Для этой конфигурации рассчитан один экземпляр приложения, как и для основной SQLite.

Обычный `scripts/backup.mjs` копирует только основную БД, без аудио. Для согласованного архива аудио и его лимитов используй короткое окно остановки приложения. Следующий пример сохраняет архив **на хосте**, а не внутри контейнера; каталог назначения должен быть заранее создан с доступом только администратора:

```bash
# Выполнять из каталога проекта, после первого успешного прослушивания.
set -eu
audio_backup="/var/backups/slyshat/audio-$(date -u +%Y%m%dT%H%M%SZ).tar.gz"
docker compose stop app
trap 'docker compose start app' EXIT
docker compose run --rm -T --no-deps --entrypoint tar app \
  -czf - -C /data audio > "$audio_backup.partial"
mv "$audio_backup.partial" "$audio_backup"
docker compose start app
trap - EXIT
```

Восстанавливай доверенный архив в `/data` при остановленном приложении, под пользователем контейнера. Не восстанавливай старый `usage.sqlite` поверх текущего в день активной генерации: это откатит счётчик расходов. Для такого переноса сначала поставь `TTS_DAILY_CHAR_LIMIT=0`, восстанови архив, а новый лимит включи после смены суток UTC. Копируй архивы вместе с основной БД на отдельный носитель. Само обновление приложения не требует восстановления бэкапа.

## Если звук не работает

- **Нейроозвучка ещё не подключена:** проверь `TTS_PROVIDER` и пересоздание контейнера. Без настройки остаётся явно подписанный системный синтез.
- **Сервис отклонил доступ:** проверь ключ, ограничения API/IP, включение Cloud Text-to-Speech и оплату. Не выводи `.env` или полный `docker compose config` в публичные логи.
- **Достигнут лимит:** уже созданные записи продолжают работать; для новых дождись следующих суток либо осознанно измени лимит.
- **Запись готова, нажми ещё раз:** браузер заблокировал воспроизведение после асинхронного запроса. Повторное нажатие запускает уже готовый файл без новой генерации.
- **Сбой сети или ошибка провайдера:** плеер показывает ошибку. Автоматической платной повторной генерации и незаметного переключения на системный голос нет. Системный голос можно выбрать вручную.

## Проверка и границы реализации

Автоматические проверки используют подмену ответа провайдера, без оплаты: формат запроса, каталог разрешённых реплик, отдельные голоса, объединение запросов, сохранение кэша и лимитов, ошибки, отмена проигрывания, сохранение настроек, авторизация и HTTP-маршруты в production-сборке. Это не проверка звучания настоящего голоса. Реальный запрос Google и прослушивание на телефоне требуют ключа и проверки после развёртывания. Голоса синтетические; студийные записи дикторов не добавлены.

Документация провайдера: [Chirp 3 HD](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd), [голоса и языки](https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types), [REST synthesize](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/text/synthesize), [API keys](https://docs.cloud.google.com/docs/authentication/api-keys-use), [цены](https://cloud.google.com/text-to-speech/pricing).
