# Следующие задачи для OpenClaw

Переход на отобранный каталог, SQLite-схема 8. Репозиторий: https://github.com/tikhomirovsrg/slyshat. Сайт: https://tikhomirovsrg.ru/. Этот документ не подтверждает обновление работающего сервера.

## Обновление

1. Найти существующую установку и сохранить резервную копию БД вне контейнера. Сохранить `.env`, имя Compose-проекта и подключённый том. Не менять OpenClaw Gateway.
2. Прочитать `AGENTS.md` и [STORY-COURSE.md](STORY-COURSE.md) и [COMICS.md](COMICS.md). Сохранить пользовательские локальные изменения до обновления.
3. В каталоге приложения выполнить:

```sh
git pull --ff-only
docker compose up -d --build app
docker compose exec -T app node scripts/migrate.mjs
```

Миграция должна показать `schemaVersion: 8`, `comicBoards: 2000` и десять групп по 200 в `storyCourse`. Повторный запуск идемпотентен. Не выполнять `docker compose down -v`.

## Исправление входа на телефоне и компьютере

Клиентские запросы прогресса и профиля теперь вызывают `fetch` с правильным браузерным контекстом. Прежний вызов как метода объекта мог давать `Illegal invocation`, после чего интерфейс ошибочно показывал отсутствие связи и скрывал вход. Тайм-аут использует `AbortController`, включая браузеры без `AbortSignal.timeout()`. При сбое проверки остаётся прямая кнопка Яндекс ID.

После пересборки проверить в новом окне без сессии: появляется кнопка «Войти с Яндекс ID», `/api/progress` отвечает 401 с `oauthReady: true`; это ожидаемый ответ до входа. Сам `/api/auth/yandex` должен переводить к форме Яндекса. Успешный возврат и продолжение на втором устройстве проверяются владельцем аккаунта. Не сбрасывать БД, cookies всех пользователей или секрет приложения ради этого исправления.

## Проверка

- Главная и `/api/health` отвечают 200, контейнер healthy, HTTPS работает.
- `/api/stories?language=en` и `/api/stories?language=it`: `total: 150`, по 30 на уровень, позиции 1–150. С `includeArchived=1` отдельно возвращаются 973 прежних варианта на язык.
- В деталях `/api/stories?id=coffee-it` есть `comic.scenes` для всех узлов; `/comics/v1/female-neutral.webp` и `/comics/v1/male-neutral.webp` отвечают 200.
- Один раздел «Истории», отдельного «Аудио» нет. История показывает комикс и выбор продолжения; новые 246 имеют записи реплик и вариантов ответа в `public/audio/expansion`.
- Проверить исходную и новую историю, воспроизведение сцены и ответов, разные финалы, переход 30 → 31 и отсутствие следующей после №150. Фильтры не меняют последовательность курса. Сохранённые ответы на задания после прежнего чтения остаются доступны, но не добавляют прослушивания.
- На ширинах 360, 390 и 768 px нет горизонтального скролла страницы; реплики переносятся, кнопки доступны пальцем. Проверить реальный Safari/iPhone или Chrome/Android.
- Текст отмечается как помощь. Прерванная сцена не считается прослушанной. Другой путь сохраняет прежнее завершение и открытые финалы.
- Без входа `/api/progress` и `/api/profile` отвечают 401. Проверить вход через Яндекс и продолжение той же ветки на другом устройстве. При необходимости попросить владельца выполнить только интерактивный вход.
- Старые результаты и черновики на месте. Backup/restore проверять на отдельной базе, не заменяя рабочую.

Готовые записи находятся в `public/audio/course`, `public/audio/library`, `public/audio/characters` и `public/audio/expansion`; сохранять все каталоги вместе с manifest. Генерация на сервере и ключ синтеза для комиксов не требуются. Сообщить фактический коммит и результаты проверок. Публикация в GitHub не обновляет контейнер автоматически.

## После обновления

1. Прослушать примеры A1–C1 обоих языков с преподавателем: произношение, длительность, сложность.
2. Проверить сцены с человеческими персонажами: осмотр детали отмечает чтение, коллекция не раскрывает будущие финалы, статичный режим работает. Иллюстрации и декорации переиспользуются.
3. Проверить новый каталог и архив по [CATALOG-TRANSITION.md](CATALOG-TRANSITION.md). Прежние варианты не возвращать в активный каталог ради количества. Новая озвучка технически проверена; прослушивание преподавателем остаётся отдельной задачей.
4. Выпускать материалы версионированными миграциями. Перед публикацией проверять ветви, аудио, межустройственное продолжение и резервные копии.
