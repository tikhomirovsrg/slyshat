# Слышать 3.0 — комиксы с выбором сюжета

Единый раздел «Истории»: комикс, готовая озвучка и решения, которые меняют продолжение и финал. Раздел «Аудио» убран из навигации. Каталог, «Мой день» и прогресс используют общий курс. Старые упражнения и письменные работы остаются в архиве прогресса и дополнительных разделах.

## Материалы и порядок

- По 1000 историй на английском и итальянском. По 200 на A1, A2, B1, B2 и C1.
- В каждую тысячу включены прежние 20 историй с исходными ID и ветвлениями.
- Остальные 980 на язык — интерактивные варианты 25 базовых ситуаций с 8 затруднениями, адаптированные к уровням. Общие сцены переиспользуются. Это не 1000 независимых авторских сюжетов; происхождение объясняется в интерфейсе.
- У новых вариантов два последовательных решения и четыре различных финала. Выбор меняет способ решения проблемы и способ согласования с группой. Отдельных тестовых ответов в комиксном прохождении нет.
- Нумерация 1–1000 внутри каждого языка закреплена выпуском. После 200 идёт 201 следующего уровня. Фильтры и страницы не меняют следующую историю.
- Можно проходить по порядку или выбирать любую историю. В финале — «Следующая история» и «Другой путь».
- A1–C1 — учебная разметка. Экспертная проверка CEFR и прослушивание носителем не выполнялись.

## Интерфейс и доступность

Контрастные комиксные панели, бумажный фон, цветные плашки, крупные кнопки. На телефоне каталог и сцена идут одной колонкой; при ширине до 560 px управляющие кнопки располагаются вертикально, длинные реплики переносятся. Есть фокус клавиатуры, подписи кнопок, скрытый от экранного диктора декоративный рисунок и поддержка reduced motion.

Текст реплик изначально скрыт. Можно слушать или раскрыть текст/перевод для перехода дальше. Помощь текста фиксируется отдельно; прерванная запись не считается прослушанной. Иллюстрации — существующие SVG-сцены, повторяющиеся в разных историях; индивидуального рисунка для каждого из 2000 комиксов нет.

## Хранение и совместимость

SQLite-схема 6 добавляет `story_course_releases` и `story_course_entries`. Выпуск `content/story-course/course-v1.json` неизменяемый; миграция проверяет SHA-256 и идемпотентно добавляет содержимое.

`StudyProfile.journey` содержит активную историю каждого языка, последовательность выборов, прослушанные сцены, открытые подсказки и дату финала. Синхронизация использует существующий аккаунт, ревизии и разрешение конфликтов. Сервер проверяет, что последовательность проходит по существующему графу и финал действительно достигнут.

Старые таблицы прогресса, попытки, результаты аудиопрактики, черновики и слова сохраняются. Прежний путь истории подхватывается, если для неё ещё нет нового сохранения. Экспорт/импорт профиля включает новый маршрут. Новое прохождение другого пути заменяет текущую ветку комикса. Дата первого завершения и открытые финалы сохраняются, счётчик пройденных историй не уменьшается. Запись о завершении остаётся также в журнале активности в пределах его лимита.

## Записи и генерация

Готовые MP3 лежат в `public/audio/course`; сцены из `public/audio/library` тоже нужны. Манифест связывает текст, голос, исходный выпуск, SHA-256 файла и границы фрагмента. 698 новых озвученных фрагментов включают узлы всех прежних историй и дополнительные развилки. Использованы Kokoro Emma/George и Sara/Nicola; это синтез, а не студийная запись.

Генерация выполняется локально: Linux-runner `offline.py` запрещает интернет-сокеты через seccomp, а телеметрия ONNX Runtime отключается до создания сессии. Если запрет невозможно установить, runner завершается с ошибкой. Модели и PCM-кэш находятся вне Git. Команда при подготовленных моделях:

```sh
python scripts/story-course/build.py
python scripts/audio-library/offline.py scripts/audio-library/generate.py --model /path/kokoro-v1.0.onnx --voices /path/voices-v1.0.bin --cache /path/pcm-cache --workers 4 --threads 2 --source content/story-course/course-v1.json --output public/audio/course
```

Для работы Docker генерация и ключ API не требуются.

## Обновление через OpenClaw

1. В существующем каталоге проекта сохранить резервную копию БД вне контейнера. Использовать прежнее имя Compose-проекта, `.env` и volume.
2. Получить изменения и пересобрать приложение:

```sh
git pull --ff-only
docker compose up -d --build app
docker compose exec -T app node scripts/migrate.mjs
```

3. Убедиться, что миграция сообщает `schemaVersion: 6` и десять групп по 200 в `storyCourse`.
4. Проверить `/api/stories?language=en` и `/api/stories?language=it`: `total` равен 1000, все уровни имеют по 200. Открыть историю, проверить звук, два разных пути и переход 200 → 201. Продолжить сохранённую историю на другом устройстве.

Не выполнять `docker compose down -v`. Обновление GitHub не обновляет уже работающий контейнер автоматически.

## Проверки перед публикацией

`npm run check`, `npm test`, `npm run build`, `npm run test:production`. Проверяются достижимость всех ветвей, отдельные последствия решений, последовательность курса, помощь текста, валидность аудиофрагментов, миграция, сохранение между сессиями и после перезапуска, backup/restore. Проверка в реальном мобильном браузере и слуховая редактура носителем — отдельные этапы.


## Управление сценой (3.1)

- Скорость меняется рядом с кнопкой «Слушать сцену»: 0,5 / 0,75 / 0,9 / 1 / 1,1 / 1,25 / 1,5×. Уже звучащая запись продолжает с текущего места; следующие реплики используют выбранную скорость. Настройка сохраняется существующим механизмом прогресса, вместе с остальными настройками выбранной языковой истории.
- «С начала» доступно в любом кадре. Останавливает звук, скрывает текст и перевод, очищает маршрут и отметки текущей попытки. Дата первого завершения, открытые финалы и прежняя история занятий сохраняются. На первом кадре кнопка также сбрасывает подсказки и прослушивание этой попытки.
- `app/comic-scene-art.tsx` рисует кадр по текущему узлу и сделанным выборам: меняются композиция, позы и предмет в сцене; выделяется говорящий персонаж. Будущие узлы и реплики не раскрываются. Это общие векторные иллюстрации, а не отдельные авторские рисунки для каждой из 2000 историй. При уменьшенной анимации в настройках устройства движение отключается, смена кадра остаётся.
- Высота шапки определяется содержимым: нижняя линия располагается под обоими рядами, а не пересекает меню. Навигация и новые элементы управления адаптированы к узкому экрану.

Проверка обновления: изменить скорость во время реплики и перед следующей; перезапустить в середине и после финала; обновить страницу и открыть другое устройство; сравнить иллюстрации двух веток и финалов. Проверить ширину 360–390 px, увеличение текста и навигацию клавиатурой. Автоматические проверки не заменяют проверку внешнего вида в реальном браузере.
